## 对两份报告的取舍

| 议题 | 复核结论 |
|---|---|
| 粗层求解是速度热点 | 支持。两次完整运行都占总模拟时间约 56%。源码 `solve_coarse_shadow()` 每轮单独执行曲率、残差范数和预条件残差内积，`device_dot()` 通过 Thrust 返回主机标量；MAS setup 从 GPU 下载 BCOO 行列、在 CPU 建图再上传。 |
| 粗方向表达能力不足 | 支持作为独立质量问题。已有冻结样本中，精确粗解不能修复低预测下降；不能通过放松阈值、缩减 post10 或删除校验来制造加速。 |
| 所有可折叠连通图都应强制合成一个 aggregate | 尚未成立。`(2)` 报告把它作为优先语义门，但现有 Green 快照中运行时稳定分组的最佳方向拟合误差为 62.86%，强制全局连通合并则恶化到 84.96%。需要先用论文算法定义和特制图对照证明语义，再考虑改变映射；它也不能直接作为当前速度补丁。 |
| 强制完整 paper12 affine basis | 值得单独消融，但不能推断它会修复方向质量。平面布料的 rest 坐标可能使 12-DoF 列线性相关；rank-aware 删除相关列未必改变子空间。 |
| 改成 coarse CEMAS16 / 全 GPU MAS | 有潜在价值，但属于较大、数值风险较高的后续工作。先用同一冻结矩阵衡量 setup、SpMV、dot、预条件应用与方向质量，再决定替换路径。 |
| profiling 同步污染计时 | 源码中每次 Galerkin/线性系统确有 CUDA event 同步；应拆分低扰动计时与诊断构建。但在实现前不能把当前观察到的 56% 全归咎于 profiler。 |

## Nsight 定位与 MAS 局部校验快路

`perf_diag/agipc_profile27_20260916.nsys-rep` 是当前内积合并版本的 27 帧剖析，不代表正式场景计时。CUDA API 汇总中，同步 `cudaMemcpy` 调用 13,268 次、累计 3.571 s；其中设备到主机复制 12,855 次，8/16/4 字节分别有 6,672/2,744/2,353 次，说明主机依赖的标量读取是实际热点。该样本的 99 次 MAS 尝试中，setup/局部校验累计 394.3/324.9 ms，`check_local_matrices` kernel 累计约 307.1 ms。完整 35 帧接触段的图复用很少，因此仅优化复用分支无法解决主成本。

本轮先对 `TraditionalMAS32Preconditioner.cu::check_local_matrices` 做保守快路。原实现对每个 96×96 局部矩阵及其对称近似逆各做一次完整 Cholesky；新的执行次序先完成局部矩阵 SPD 检查和原有 FP64 完整逆残差。设局部矩阵 `A` 已 SPD、存储的 `B` 对称，若 `||I-AB||_F/sqrt(96) <= 1e-3`，则 `||I-AB||_2 < 0.01 < 1`，由 `AB` 与对称的 `A^(1/2)BA^(1/2)` 相似可推出 `B` SPD。此时省去第二次 Cholesky；非有限、局部非 SPD、残差超限的路径仍执行原逆矩阵 Cholesky，因此不放松原有失败门。

固定 1,415 块真实粗系统含 53 个局部矩阵。新旧版本的 GPU 局部诊断 JSON 完全一致，均与 CPU 诊断一致。`--mas32-self-test` 退出 0，正常、局部非 SPD、逆非 SPD、NaN、逆残差超限等六个样例均通过预期断言。固定系统上三轮交错 Nsight 检查的 `check_local_matrices` kernel 时间为：

| 轮次 | 原版 | 快路 |
|---:|---:|---:|
| 1 | 3.942 ms | 3.011 ms |
| 2 | 5.318 ms | 3.825 ms |
| 3 | 5.821 ms | 3.695 ms |
| 中位数 | **5.318 ms** | **3.695 ms** |

该固定 kernel 的中位耗时下降 **30.5%**，但样本仅三轮，且不能外推为粗层或全场景加速。新版本的一次 27 帧接触运行完成：有限顶点、地面穿透 0、74 次 Newton、3,274 次线性迭代、101 次候选采用、无回退或 MAS 局部失败。与上一次旧版 27 帧终态 RMS 差 `0.000222`；两次 Newton 轨迹不同，不作为严格数值等价或速度比例。下一项高优先级是减少粗 PCG 仍存在的逐迭代主机标量读取，并在同一冻结系统上核对残差、方向与 API 次数。

## 粗 PCG 标量常驻 GPU 试验与 MAS 同步优化

在上述版本基础上，先试验让粗 PCG 的曲率和双残差内积保留在设备端，每轮只回传一次 40 字节状态。27 帧 Nsight 样本中，原版的 16 字节设备到主机拷贝为 2,748 次，初版试验仅 109 次；新版增加约 2,884 次 40 字节状态拷贝。`--agipc-self-test`、`--mas32-self-test` 和接触场景均通过，候选仍全部采用。但每轮新增的状态 kernel 抵消了同步节省；把状态判断并入向量 kernel 后，交错的 27 帧运行仍未显示稳定提速。在更新次数接近的样本中，原版 89 次更新的粗层耗时为 1,154–1,247 ms，合并 kernel 后 89/90 次更新分别为 1,386/1,383 ms。由于接触轨迹波动，这不是严格配对速度比，但足以否决当前实现。**该 PCG 试验代码已撤销**，未改变保留版的求解行为。

随后只删除 `RuntimeCoarseMas::setup()` 两处分支末尾的 `cudaDeviceSynchronize()`。矩阵刷新、预条件器应用和局部校验依次在默认流执行；后续校验要回读设备结果，因此仍会在需要结果时等待 GPU。没有删除任何数值门。旧版和新版本分别交错运行固定 27 帧场景，原始记录在 `perf_diag/agipc_sync_*.json` 与 `agipc_sync_*.log`；其中两次较接近的样本为：

下一轮若要优化 PCG，应在冻结粗矩阵上建立直接调用生产求解循环的可重复基准，再尝试减少 kernel 数或改变算法；仅按 D2H 拷贝次数判断收益会误导。当前改动的结论限于去掉两次显式同步、通过现有数值门，并降低 Nsight 中显式全设备同步开销，**尚无可信的全场景加速结论**。

## MAS 固定图复用快路
